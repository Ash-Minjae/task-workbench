# 앱 기능 구현

기존 실행 명령과 프로젝트 구조부터 확인한다. 화면 모양이나 프레임워크를 먼저 정하지 않는다. 사용자의 입력이 처리되어 필요한 결과에 도달하는 흐름을 하나 정하고, 그 흐름이 실제로 동작하는 범위부터 구현한다.

요구된 상태가 어디에 저장되는지 확인한다. 화면 메모리의 값이 영구 저장을 대신하지 않도록 하고, 저장이 요구됐다면 재조회나 새로고침 후 결과로 확인한다. 시연용 고정 데이터와 실제 처리 결과가 섞이지 않게 한다.

경계에서 입력을 검증하고 실패 시 사용자가 다음 행동을 알 수 있게 한다. 비동기 처리가 있으면 대기, 성공, 실패를 구분하고 중복 실행이나 일부만 저장되는 경우를 확인한다. 접근 권한이 요구되면 화면 표시뿐 아니라 실제 데이터 접근 경로에서 검사한다.

필수 흐름의 정상 입력과 실제로 실패해야 하는 입력을 실행한다. 프로젝트의 기존 테스트와 도구를 우선하고, 화면 확인은 환경이 허용하는 방식으로 수행한다. 자동 화면 조작이 제한된 환경에서는 해당 도구를 사용하지 않는다.

작동이 확인된 범위를 유지하면서 중요한 누락을 메운다. 외형을 다듬는 변경 때문에 필수 결과와 검증을 밀어내지 않는다. 실행 명령, 실제 확인 결과와 미완성 조건을 남기고 [artifact-checking](../artifact-checking/SKILL.md)으로 제출 요구를 대조한다.
