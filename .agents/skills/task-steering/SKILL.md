# 문제 정의와 작업 조정

과제 원문과 제공 파일을 읽고 결과물이 충족할 조건을 정리한다. 기능을 미리 가정하지 않는다. 분석, 문서, 코드 중 요구된 결과물 형태를 따른다.

최종 사용자와 의사결정, 입력과 필수 출력, 제약과 확인 방법을 파악한다. 원문에 없는 핵심 정책만 업무 담당자에게 질문한다. 질문할 수 없으면 가정과 영향을 표시한다.

작업은 실제 입력에서 요구된 출력까지 확인할 수 있는 단위로 나눈다. 요청에 목표, 변경 범위, 유지할 조건과 완료 확인 방법을 포함한다. 자율 실행 범위는 오류의 영향과 복구 가능성에 맞춘다.

필수 조건을 충족하는 경로부터 만든다. 새 요구나 오류가 나오면 남은 시간과 검증 비용을 보고 순서를 조정한다. 고정된 분 단위 시간표를 강요하지 않는다. 끝내지 못한 필수 조건은 누락과 영향을 남긴다.

표 데이터 분석에는 [tabular-analysis](../tabular-analysis/SKILL.md), 앱 구현에는 [app-delivery](../app-delivery/SKILL.md)를 과제에 맞게 읽는다. 검증에는 [artifact-checking](../artifact-checking/SKILL.md), 설명에는 [explain-artifact](../explain-artifact/SKILL.md)를 사용한다. [작업 노트](../../../templates/work-notes.md)는 선택 양식이며 실제 제출 형식이 우선한다.
