# 결과 검증

요구사항을 관찰 가능한 확인 방법에 연결한다. 검사는 실제 결과를 읽어야 한다. 파일의 존재나 AI의 완료 보고만으로 성공을 결론내리지 않는다.

## 데이터

Python 3.10 이상이 있으면 [tablecheck.py](../../../tools/tablecheck.py)를 선택해 사용한다. [명령과 한계](../../../docs/tools.md)를 읽고 실제 열 이름과 업무 정책에 맞게 옵션을 정한다.

- inspect는 구조, 결측, 중복과 숫자를 관찰한다. 반환 코드0은 데이터의 적절성 판정이 아니다.
- check는 지정한 조건만 판정한다. 숫자처럼 보이는 식별자를 임의로 변환하거나 결측을 제거하지 않는다.
- compare는 전후 행 구성, 숫자 합계와 집단별 영향을 비교한다. 변화가 올바른지는 업무 정책으로 판단한다.

원본을 보존하고 처리 이유와 영향을 확인한다. 알려진 잘못된 입력을 넣어 검사가 실패하는지도 확인한다. 표본 계산은 별도로 대조한다.

## 코드와 제출물

프로젝트가 제공한 테스트와 실행 방법을 우선한다. 오류를 재현한 입력으로 수정을 확인하고 관련 정상 경로도 확인한다. 웹 화면은 허용된 방법으로 사람이 동작을 확인한다.

[artifactcheck.py](../../../tools/artifactcheck.py)는 명시한 파일과 형식, 간단한 구조만 확인한다. 분석의 타당성은 검사하지 않는다. [검사 계약 예시](../../../practice/artifacts.json)는 연습용이며 실제 제출 조건으로 대체한다.

실제 실행한 명령과 관찰 결과, 실패와 한계를 짧게 남긴다. 확인할 수 없는 항목은 미확인으로 남긴다.
